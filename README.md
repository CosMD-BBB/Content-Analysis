# Content Studio

ระบบจัดการคอนเทนต์ของทีม: แยกโปรเจกต์ตามบริษัท, วางตารางงาน, ขั้นตอนอนุมัติ, กดเผยแพร่ไปหลายช่องทาง, งานที่ต้องโพสต์เอง, รายงานผล และรายการโปรด

**สถานะ: ระยะที่ 1 พร้อมใช้งาน** ทุกช่องทางทำงานแบบ "โพสต์เอง + กรอกผลเอง" ไปก่อน การเชื่อมต่อ API จริงจะเปิดทีละช่องทางในระยะ 2–4
ดูรายละเอียดใน [เอกสารออกแบบ](docs/specs/2026-11-13-content-studio-design.md) และ [แผนงานระยะ 1](docs/plans/2026-11-13-content-studio-phase1.md)

## มีอะไรบ้าง

| เมนู | ทำอะไร |
|---|---|
| ทุกโปรเจกต์ / ตัวสลับโปรเจกต์ | 1 โปรเจกต์ = 1 บริษัท ข้อมูลไม่ปนกัน คนเดียวอยู่ได้หลายโปรเจกต์คนละบทบาท |
| ภาพรวม | งานของฉัน (ตามบทบาท), 7 วันข้างหน้าพร้อมรูปย่อ, ผลงานดีสุด, ความเคลื่อนไหว |
| ปฏิทินคอนเทนต์ | รายเดือน/รายสัปดาห์ มีรูปย่อ ลากย้ายวันได้ กรองตามช่องทาง สถานะ ประเภทงาน คน |
| คลังคอนเทนต์ | ตารางพร้อมรูปย่อ ประเภทงาน ค้นหา กรอง กดดาว |
| หน้ารายละเอียดงาน | ตัวอย่างโพสต์ตามแต่ละแพลตฟอร์ม (9:16, 4:5, 1:1, 16:9, การ์ด LINE, บทความ), อัปโหลดรูป/วิดีโอ, คอมเมนต์ปักหมุดบนรูป, ประวัติการแก้ไข |
| อนุมัติ & เผยแพร่ | รออนุมัติ → พร้อมเผยแพร่ (ตอนนี้ / ตั้งเวลา) → ต้องโพสต์เอง (คัดลอกแคปชัน ดาวน์โหลดไฟล์ วางลิงก์ปิดงาน) |
| รายงานผล | ยอดวิว, Engagement, ER, แยกตามช่องทาง ประเภทงาน หมวด, ช่วงเวลาที่โพสต์แล้วได้ผลดี, ตัวเลขที่ยังขาด, ดาวน์โหลด CSV |
| ช่องทางที่เชื่อมต่อ | ความสามารถ API ของแต่ละช่องทาง และคู่มือเชื่อมต่อ 5 ขั้นสำหรับแอดมิน |
| ทีมและสิทธิ์ / ตั้งค่าโปรเจกต์ | เพิ่มสมาชิก, ลิงก์เชิญ, เปลี่ยนบทบาท, ประเภทงาน (Broadcast, VDO, Ads …), หมวดคอนเทนต์ |
| แจ้งเตือน | กระดิ่งในระบบ + อีเมล (รออนุมัติ, ถูกขอแก้, อนุมัติแล้ว, ต้องโพสต์เอง, ใกล้กำหนด) |

คนแรกที่สมัครเป็น **เจ้าของระบบ** สร้างโปรเจกต์ได้ คนที่สมัครเองจะยังไม่เห็นข้อมูลจนกว่าแอดมินจะเพิ่มเข้าโปรเจกต์

## ขึ้นระบบจริง

ใช้ **Hostinger VPS** (เว็บ + worker + PostgreSQL + HTTPS ในเครื่องเดียวด้วย Docker) และอัปเดตอัตโนมัติจาก GitHub
ทำตามขั้นตอนใน **[docs/deploy.md](docs/deploy.md)**

## ลองบนเครื่อง Mac

รันทั้งระบบบน Mac ด้วย Docker Desktop คำสั่งเดียว พร้อมข้อมูลตัวอย่าง ดู **[docs/run-on-mac.md](docs/run-on-mac.md)**

## รันในเครื่อง (สำหรับผู้พัฒนา)

ต้องมี Node.js 22 และ PostgreSQL 16 (หรือ Docker)

```bash
cp .env.example .env
```

```bash
docker compose up -d db
```

```bash
npm install
```

```bash
npm run db:migrate
```

```bash
npm run dev
```

เปิด http://localhost:3000 แล้วสมัครบัญชีแรก · งานตั้งเวลาต้องรัน worker คู่กัน:

```bash
npm run worker
```

ทดสอบ:

```bash
npm test
```

ทดสอบทั้งระบบผ่านเบราว์เซอร์ (ต้องรันเว็บกับฐานข้อมูลว่าง):

```bash
E2E_BASE_URL=http://localhost:3000 npm run e2e
```

### โครงสร้างโค้ด

| โฟลเดอร์ | เนื้อหา |
|---|---|
| `app/` | หน้าเว็บและ server actions (Next.js App Router) |
| `components/` | ส่วนประกอบหน้าเว็บ |

## ความสามารถของ API แต่ละช่องทาง

| ช่องทาง | โพสต์อัตโนมัติ | ดึงสถิติ | หมายเหตุ |
|---|---|---|---|
| Facebook Page | ได้ | ได้ | Meta Graph API, ต้องผ่าน Meta App Review |
| Instagram | ได้ | ได้ | ต้องเป็นบัญชี Business/Creator, มีโควตาโพสต์ต่อวัน, ไม่รองรับบทความยาว |
| YouTube | ได้ (เฉพาะวิดีโอ/Shorts) | ได้ | มีโควตา API รายวัน, แอปที่ยังไม่ผ่านการตรวจของ Google จะอัปเป็น Private |
| TikTok | บางส่วน | บางส่วน | ถ้ายังไม่ผ่าน audit ส่งเข้า Inbox ในแอปแล้วต้องกดโพสต์เอง, สถิติมีแค่วิว/ไลก์/คอมเมนต์/แชร์ |
| X | บางส่วน | บางส่วน | ต้องใช้แพ็กเกจ API แบบเสียเงิน |
| Lemon8 | **ไม่ได้** | **ไม่ได้** | ไม่มี API สาธารณะ → ระบบสร้างงาน "ต้องโพสต์เอง" และให้กรอกตัวเลขเอง |
| LINE OA | ได้ (บรอดแคสต์) | บางส่วน | สถิติเป็นแบบรวมต่อข้อความ, โควตาข้อความตามแพ็กเกจ |
| เว็บไซต์ (WordPress) | ได้ | ได้ (GA4) | WordPress REST API + Google Analytics 4 Data API |

เงื่อนไข API ของแต่ละแพลตฟอร์มเปลี่ยนบ่อย ต้องตรวจเอกสารล่าสุดของแต่ละเจ้าอีกครั้งก่อนเริ่มพัฒนาจริง

### กติกาเวลากดเผยแพร่

แต่ละช่องทางของคอนเทนต์ชิ้นหนึ่งจะได้ผลเป็นอย่างใดอย่างหนึ่ง:

1. **โพสต์อัตโนมัติ**: เชื่อมต่อแล้ว และ API รองรับประเภทงานนั้น
2. **ส่งเป็นแบบร่าง**: เช่น TikTok ที่ยังไม่ผ่าน audit ต้องไปกดโพสต์ในแอป
3. **ต้องโพสต์เอง**: ไม่มี API, ยังไม่เชื่อมต่อบัญชี หรือ API ไม่รองรับประเภทงาน

ข้อ 2 และ 3 จะเข้าแท็บ "ต้องโพสต์เอง" พร้อมปุ่มคัดลอกแคปชัน เมื่อโพสต์เสร็จให้วางลิงก์โพสต์เพื่อปิดงาน
ถ้าช่องทางนั้นดึงสถิติผ่าน API ได้ ระบบจะใช้ลิงก์นั้นติดตามผลต่อ ถ้าดึงไม่ได้ จะขึ้นในรายงานว่า "ตัวเลขที่ยังขาด" ให้กรอกเอง
