# Content Studio: เอกสารออกแบบระบบจริง

วันที่ 13 พ.ย. 2569 · สถานะ: **อนุมัติแล้ว** (13 พ.ย. 2569)

## 1. ทำไมต้องมีระบบนี้

ทีมคอนเทนต์ดูแลหลายบริษัท (หลายโปรเจกต์) และโพสต์หลายช่องทาง ตอนนี้การวางตาราง การอนุมัติ การโพสต์ และการเก็บผลกระจายอยู่หลายที่
ระบบนี้รวมทุกอย่างไว้ที่เดียว: วางแผน → อนุมัติ → กดเผยแพร่ครั้งเดียวแล้วระบบโพสต์ให้ทุกช่องทางที่ทำได้ → บอกชัดว่าช่องทางไหนต้องโพสต์เอง → ดึงผลกลับมาเป็นรายงาน

ต่อยอดจาก prototype ใน `prototype/` (หน้าตาและขั้นตอนใช้เป็นต้นแบบ)

## 2. เป้าหมาย

- ทีมหลายคนใช้ข้อมูลชุดเดียวกันจริง ล็อกอินจริง สิทธิ์ตามบทบาท
- แยกโปรเจกต์ตามบริษัท สลับไปมาได้ ข้อมูลแต่ละบริษัทไม่ปนกัน
- เห็นคอนเทนต์เป็นรูป ทั้งในปฏิทิน คลัง หน้าอนุมัติ และรายงาน
- แอดมินที่ไม่ใช่โปรแกรมเมอร์เชื่อมต่อช่องทางเองได้ ด้วยปุ่มและคำแนะนำทีละขั้น
- กดเผยแพร่แล้วโพสต์อัตโนมัติในช่องทางที่ API รองรับ ช่องทางอื่นกลายเป็นงาน "ต้องโพสต์เอง"
- รายงานผลจาก API และจากตัวเลขที่กรอกเอง โดยบอกที่มาของตัวเลขเสมอ

## 3. ไม่ทำในรอบนี้ (non-goals)

- ซื้อหรือจัดการโฆษณา (ยิงแอด) ผ่านระบบ: งานประเภท Ads อยู่ในตารางและขั้นตอนอนุมัติได้ แต่ไปตั้งแอดใน Ads Manager เอง
- ตัดต่อวิดีโอ / ออกแบบกราฟิกในระบบ
- แอปมือถือ (ใช้เว็บบนมือถือได้)
- โพสต์ Lemon8 อัตโนมัติ (ไม่มี API)

## 4. สิ่งที่ห้ามเกิด (anti-goals)

- ระบบโพสต์คอนเทนต์ที่ยังไม่ได้อนุมัติ
- คนของบริษัท A เห็นข้อมูลหรือบัญชีโซเชียลของบริษัท B
- token ของบัญชีโซเชียลรั่ว (เก็บแบบเข้ารหัส ไม่ส่งไปหน้าเว็บ)
- รายงานแสดงตัวเลขที่กรอกเองปนกับตัวเลขจาก API โดยไม่บอก

## 5. ข้อจำกัด

- การเชื่อมต่อจริงต้องให้แพลตฟอร์มอนุมัติแอปก่อน (Meta App Review, Google verification, TikTok audit, X แพ็กเกจเสียเงิน) ระหว่างรอ เชื่อมได้เฉพาะบัญชีที่ใส่เป็นผู้ทดสอบ
- การตั้งค่าฝั่งนักพัฒนา (สร้างแอปในแต่ละแพลตฟอร์ม) ทำครั้งเดียวโดยผู้พัฒนา แอดมินในทีมไม่ต้องเห็นส่วนนี้
- โค้ดต้องย้ายเซิร์ฟเวอร์ได้ ไม่ผูกกับผู้ให้บริการเจ้าใดเจ้าหนึ่ง
- ทีมใช้ภาษาไทยเป็นหลัก

## 8. ส่วนประกอบของระบบ

### 8.1 โปรเจกต์ (แยกบริษัท)

- โปรเจกต์ = 1 บริษัท/แบรนด์ มีช่องทาง สมาชิก คอนเทนต์ ประเภทงาน หมวดคอนเทนต์ เป็นของตัวเอง
- เมนูสลับโปรเจกต์ที่มุมซ้ายบน (จำโปรเจกต์ล่าสุดไว้) และหน้า "ทุกโปรเจกต์" สรุปงานรออนุมัติและงานต้องโพสต์เองของทุกโปรเจกต์ที่ตัวเองอยู่
- ผู้ใช้ 1 คนอยู่ได้หลายโปรเจกต์ และมีบทบาทต่างกันในแต่ละโปรเจกต์
- **เจ้าของระบบ** (super admin) สร้าง/ปิดโปรเจกต์ และเชิญแอดมินของแต่ละโปรเจกต์
- ทุกคำสั่งที่อ่านหรือเขียนข้อมูลต้องตรวจฝั่งเซิร์ฟเวอร์ว่าผู้ใช้เป็นสมาชิกโปรเจกต์นั้นและมีสิทธิ์ (ไม่พึ่งการซ่อนปุ่ม)

### 8.2 บทบาทและสิทธิ์ (ต่อโปรเจกต์)

ตามตารางใน prototype: ผู้ดูแลโปรเจกต์ / หัวหน้าคอนเทนต์ / ครีเอเตอร์ / ฝ่ายวิเคราะห์ (+ บทบาท "ลูกค้า" ถ้ายืนยันในข้อ 11)

### 8.3 คอนเทนต์

ฟิลด์: ชื่อ, **ประเภทงาน**, รูปแบบ (คลิปสั้น/วิดีโอยาว/รูปเดี่ยว/อัลบั้ม/บทความ), หมวด, วันเวลาลง, ผู้รับผิดชอบ, ช่องทาง, แคปชันหลัก + **แคปชันแยกช่องทาง**, ไฟล์สื่อ, ลิงก์ไฟล์งาน, สถานะ, ความคิดเห็น, รายการโปรด

**ประเภทงาน** (แก้รายการได้ต่อโปรเจกต์) ค่าเริ่มต้น:

| ประเภทงาน | หมายเหตุ |
|---|---|
| โพสต์ทั่วไป (Organic) | |
| VDO | |
| Broadcast | LINE OA / อีเมล |
| Ads | ผ่านขั้นตอนอนุมัติ แต่ตั้งแอดเองใน Ads Manager → ถือเป็นงาน "ต้องทำเอง" |
| Live | |
| บทความ / SEO | |
| KOL / Influencer | โพสต์โดยคนนอก บันทึกลิงก์และผลเอง |
| อื่นๆ | |

ประเภทงานแสดงเป็นป้ายบนการ์ด ใช้กรองในปฏิทิน/คลัง และแยกผลในรายงาน

### 8.4 รูปและตัวอย่างโพสต์

- อัปโหลดหลายไฟล์ต่อคอนเทนต์ (ลากวาง) รองรับรูปและวิดีโอ ระบบทำรูปย่อให้อัตโนมัติ ไฟล์วิดีโอใช้เฟรมแรกหรือปกที่อัปโหลดเป็นรูปย่อ
- รูปย่อแสดงทุกที่: ช่องในปฏิทิน, ตารางคลัง, การ์ดหน้าอนุมัติ, ตารางรายงาน, รายการโปรด
- งานที่ยังไม่มีไฟล์: แสดงปกกราฟิกอัตโนมัติ (สีตามหมวด + ไอคอนรูปแบบงาน)
- **ตัวอย่างตามแพลตฟอร์ม** ในหน้ารายละเอียดและหน้าอนุมัติ: กรอบแนวตั้ง 9:16 (Reels/TikTok/Shorts), 4:5 หรือ 1:1 (โพสต์ IG/FB), 16:9 (YouTube), การ์ด LINE, หน้าบทความ พร้อมแคปชันของช่องทางนั้น
- หลังโพสต์ ดึงรูปปกจริงจากแพลตฟอร์มกลับมาแทน (ช่องทางที่ API ให้)
- **คอมเมนต์ปักหมุดบนรูป**: คลิกตรงจุดบนรูปเพื่อบอกว่าต้องแก้ตรงไหน

### 8.5 ปฏิทิน

รายเดือน / รายสัปดาห์ แสดงรูปย่อ, **ลากงานย้ายวันได้** (เฉพาะคนที่มีสิทธิ์แก้งานนั้น และงานที่ยังไม่เผยแพร่), กรองตามช่องทาง สถานะ ประเภทงาน ผู้รับผิดชอบ

### 8.6 อนุมัติและเผยแพร่

เหมือน prototype: รออนุมัติ → พร้อมเผยแพร่ (เผยแพร่ตอนนี้ / ตั้งเวลา) → ต้องโพสต์เอง
- แก้คอนเทนต์หลังอนุมัติแล้ว → สถานะกลับเป็น "รออนุมัติ" อัตโนมัติ
- เก็บประวัติเวอร์ชัน (ใครแก้อะไร เมื่อไร)
- worker เป็นคนโพสต์จริง: ลองใหม่ 3 ครั้งเมื่อพลาด ถ้ายังพลาดให้กลายเป็นงาน "ต้องโพสต์เอง" พร้อมเหตุผล และแจ้งเตือน

### 8.7 เชื่อมต่อช่องทาง (สำหรับแอดมิน ไม่ต้องเขียนโค้ด)

หน้า "ช่องทาง" ของโปรเจกต์ แต่ละช่องทางมีปุ่ม **เชื่อมต่อ** ที่เปิดตัวช่วยทีละขั้น:

1. **เตรียมก่อนเริ่ม**: เช็กลิสต์ภาษาง่าย เช่น "คุณต้องเป็นแอดมินของเพจ" / "บัญชี Instagram ต้องเป็นบัญชีธุรกิจและผูกกับเพจ Facebook แล้ว" พร้อมรูปประกอบและลิงก์ไปหน้าตั้งค่าของแพลตฟอร์มนั้น
2. **เข้าสู่ระบบ**: กดปุ่ม → หน้าต่างล็อกอินของแพลตฟอร์มเปิดขึ้น → กดอนุญาต
3. **เลือกบัญชี**: เลือกเพจ/ช่อง/บัญชีที่จะใช้กับโปรเจกต์นี้
4. **ทดสอบ**: ระบบลองอ่านข้อมูลบัญชีและเช็กสิทธิ์ แสดงผลเป็น ✓ / ✗ ต่อสิทธิ์ พร้อมวิธีแก้ถ้า ✗
5. **เสร็จ**: แสดงว่าช่องทางนี้โพสต์อัตโนมัติได้แค่ไหน ดึงสถิติได้อะไร

หลังเชื่อมแล้ว: แสดงสถานะ, วันหมดอายุของการเชื่อมต่อ, ปุ่ม "เชื่อมต่อใหม่" และแจ้งเตือนล่วงหน้าก่อนหมดอายุ
แต่ละช่องทางมีหัวข้อ "ปัญหาที่พบบ่อย" เช่น ไม่เห็นเพจในรายการ, Instagram ไม่ขึ้น
ช่องทางที่ยังไม่พร้อมใช้จริง (แอปยังไม่ผ่านการตรวจ) ปุ่มขึ้นว่า "เร็วๆ นี้" และอธิบายว่ารออะไร

### 8.8 แจ้งเตือน

- ในระบบ: กระดิ่งมุมขวาบน
- อีเมล และ LINE (บอทในกลุ่มไลน์ของทีม ตั้งค่าต่อโปรเจกต์)
- เหตุการณ์: มีงานรออนุมัติ, ถูกขอแก้, อนุมัติแล้ว, โพสต์สำเร็จ/ล้มเหลว, มีงานต้องโพสต์เอง, ถึงกำหนดแต่ยังไม่ส่งงาน, การเชื่อมต่อใกล้หมดอายุ
- ผู้ใช้เลือกเปิด/ปิดแต่ละช่องทางแจ้งเตือนเองได้

### 8.9 รายงาน

- เหมือน prototype + แยกตาม **ประเภทงาน** และ **หมวด**
- **ช่วงเวลาที่โพสต์แล้วได้ผลดี**: ตารางวันในสัปดาห์ × ช่วงเวลา (heatmap) ตาม ER
- เก็บสถิติเป็นรายวัน (snapshot) เพื่อดูการเติบโตย้อนหลัง
- ป้ายที่มาของตัวเลข: API / กรอกเอง / ยังไม่มี
- ส่งออก CSV

## 11. สิ่งที่ผู้ใช้ตัดสินแล้ว

1. **ไม่มีบทบาทลูกค้า**: อนุมัติชั้นเดียวโดยทีม
2. **ล็อกอินด้วยอีเมลอะไรก็ได้ แต่ต้องสมัครก่อน**
   - หน้าสมัคร: ชื่อ, อีเมล, รหัสผ่าน (อย่างน้อย 8 ตัว)
   - (ผู้พัฒนาตัดสิน) สมัครแล้วยังไม่เห็นข้อมูลใด จนกว่าแอดมินโปรเจกต์จะเพิ่มเข้าโปรเจกต์ หรือสมัครผ่านลิงก์เชิญ
   - (ผู้พัฒนาตัดสิน) คนแรกที่สมัครในระบบเป็นเจ้าของระบบ (super admin)
   - ลืมรหัสผ่าน: ส่งลิงก์ตั้งรหัสใหม่ทางอีเมล (ถ้ายังไม่ได้ตั้งค่าส่งอีเมล เจ้าของระบบรีเซ็ตให้ได้)

## 12. ผู้พัฒนาตัดสินใจไว้แล้ว (แก้ได้)

- เวลาในระบบใช้เขตเวลาไทย (Asia/Bangkok) ทั้งหมด
- ขนาดไฟล์: รูปไม่เกิน 20 MB, วิดีโอไม่เกิน 500 MB ต่อไฟล์
- หน้าเว็บภาษาไทยอย่างเดียวในระยะ 1 แต่เขียนข้อความแยกไว้ เพื่อเพิ่มภาษาอังกฤษภายหลังได้
- ต้องมีชื่อโดเมน (เช่น content.บริษัท.com) ก่อนเปิดใช้จริง เพราะการล็อกอินและการเชื่อมต่อโซเชียลต้องใช้ที่อยู่เว็บที่แน่นอน
- สำรองฐานข้อมูลอัตโนมัติทุกวัน เก็บย้อนหลัง 7 วัน

## 13. ปล่อยให้ผู้พัฒนาตัดสินใจ

โครงสร้างตารางฐานข้อมูล, การตั้งชื่อในโค้ด, ไลบรารีย่อย, รายละเอียดหน้าตาที่ไม่ขัดกับ prototype, ข้อความในคู่มือเชื่อมต่อ (ตรวจกับเอกสารล่าสุดของแพลตฟอร์มตอนเขียน)
